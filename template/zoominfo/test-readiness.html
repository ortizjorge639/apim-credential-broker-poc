Two evidence lenses

Identity proof is not telemetry proof

Do not use success in one layer as evidence for another layer.

Delegated identity

For the baseline, verify ZoomInfo receives the signed-in test user's identity and that the read-only Lookup succeeds. Foundry sign-in alone is not backend identity proof.

Required in both routes

Gateway governance and observability

Only the Toolbox/APIM follow-on can produce APIM telemetry for this route. Default MCP telemetry includes request/tool metadata; arguments and results require payload logging.

Baseline / per-user identity

Foundry directly to ZoomInfo

Can test first

Foundry owns the per-user delegated OAuth connection. This baseline does not pass through APIM.

  1. 1
    Configure Foundry OAuth connection

    Use the customer app details, approved scopes, and Foundry's matching registered callback. Put the secret only in the secure connection setup.

  2. 2
    Connect to ZoomInfo MCP directly

    Use the provider-approved HTTPS endpoint. The local mock at 127.0.0.1 is not reachable from hosted Foundry.

  3. 3
    Call only Lookup as test user

    Confirm ZoomInfo receives the signed-in test user's identity; capture status, JSON-RPC result, and MCP isError.

PASS when That user's delegated identity is verified at ZoomInfo and the direct read-only Lookup succeeds. No APIM claim is made.
Proposed follow-on / telemetry

Toolbox through APIM

Design first

After the direct baseline, define the Toolbox endpoint, authentication, and token/identity owner before routing it through APIM.

  1. 1
    Define the actual route

    Record where Toolbox runs, the MCP URL, caller authentication, ZoomInfo auth method, and identity/token owner.

  2. 2
    Expose Toolbox MCP through APIM

    Allow only approved tools and methods; review routing, access controls, streaming, and secret-safe telemetry.

  3. 3
    Repeat Lookup and inspect evidence

    Verify the identity at ZoomInfo and observe APIM's request telemetry. Compare with the direct baseline.

PASS when Toolbox identity propagation, a successful read-only Lookup, and the APIM telemetry are observed—not assumed.

Telemetry boundary: APIM documents default MCP dimensions such as tool, client, duration, and success. Arguments/results are not included by default. The local repo's optional Credential Manager PKCE experiment is separate from this Toolbox route.

Decision rule

Run the local simulations for protocol confidence. For the real baseline, use customer inputs and Foundry's direct HTTPS connection to ZoomInfo. Test Toolbox/APIM only after its topology is defined; neither local simulation proves hosted identity or APIM telemetry.

High-ground findings

Three things to keep separate

Start with the direct route

It isolates whether Foundry can complete the user's ZoomInfo/Okta sign-in and call Lookup. It says nothing about APIM.

Add APIM to measure APIM

Telemetry and gateway controls can only be assessed after the Toolbox/APIM route is defined and exercised. Do not claim these benefits for the baseline.

One tool call is not least privilege

ZoomInfo app scopes define token permissions. The test's Lookup-only plan and APIM tool allowlist are separate controls.

Product docs are not an end-to-end proof

Official guidance supports individual components. The exact ZoomInfo + Okta + Foundry + Toolbox + APIM integration still needs customer runtime evidence.

What “complete” means

A token is not the finish line

Foundry lane evidence

Complete only after the actual Foundry-hosted call works as the intended person.

  • OAuth succeeds for the test user
  • Delegated identity is shown to be that user
  • HTTP success + no JSON-RPC error + MCP isError=false
  • Lookup behavior is verified read-only

Toolbox/APIM follow-on evidence

Complete only after the topology, identity owner, and end-to-end call are proven.

  • Toolbox hosting and token/identity ownership are documented
  • ZoomInfo confirms the identity received by the backend
  • Successful read-only Lookup through APIM
  • Observed telemetry; arguments/results excluded unless separately approved

The direct Foundry → ZoomInfo test proves the per-user baseline, not APIM governance.

Public product documentation supports individual components, but does not prove this complete customer topology. Confirm the OAuth app scopes and URLs with ZoomInfo. The proposed Toolbox/APIM follow-on needs its own design and runtime evidence.

First-party references: ZoomInfo Standard Apps, ZoomInfo PKCE, ZoomInfo scopes, ZoomInfo refresh tokens, Foundry MCP OAuth, APIM MCP telemetry. These document product capabilities, not this integrated route.
