Setup: conn2 (never consented, status Error/Unauthenticated) + access policy for APIM MSI; op GET /gh/broken, Consumption tier.
Observed (get-authorization-context, identity-type=managed):
- ignore-error=false: policy did NOT fail. Flow continued; no 424, no 500 from the policy itself.
- Variable `auth-context` was NOT set (ContainsKey=False); context.LastError=null (even with ignore-error=true).
- The 500 only appears later when an expression dereferences the missing variable (Bearer ... AccessToken).
- If you only set the header with a null-safe expression, the backend is called unauthenticated (GitHub 404 on /broken).
Conclusions: 424 NOT observed (notebook/infographic claim unconfirmed here). Always check ContainsKey/ null before set-header; gateway must return its own 401/403, otherwise unauthenticated calls leak to the backend.
Caveat: policy changes take ~30-60s to propagate; early probes hit stale policy.
