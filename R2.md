## RESOLUTION (docs + tests, 23:2x)
- Learn (get-authorization-context, usage notes): identity-type=jwt is for access policies assigned to a SERVICE PRINCIPAL; only /.default app-only tokens supported. Delegated user tokens (az account get-access-token) never match -> explains all user "Permission denied".
- Verified on conn3: SP token + sp policy -> 200; user token + useroid policy -> denied; SP token without policy (before first grant) -> denied.
- Revocation lag: after deleting `sp` policy, SP token still 200 for 8+ min (two runs). Revocation is NOT immediate on Consumption (cached authorization). Also explains stray 200s on conn1.
- Net: jwt = app-only identity gate, not per-user, and revocation is eventually-consistent (unbounded in test). R2 = PASS for SP, user-JWT unsupported by design.
